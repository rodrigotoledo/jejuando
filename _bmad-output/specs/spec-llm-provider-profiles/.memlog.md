- (direction) User wants the LLM layer decoupled so development runs against local Ollama with MedGemma1.5:latest, instead of the hardcoded OpenAI endpoint.
- (direction) User decided dev must switch between the local Ollama profile and a remote gateway (tunnel/9router) profile, selected by environment variable.
- (decision) Two profiles named local and remote, selected by env; local is the default in development.
- (constraint) The app must never require an external server in development: the local profile talks only to an Ollama instance the developer controls.
- (constraint) Ollama endpoint differs per host: Android emulator reaches the host at 10.0.2.2, a physical device uses the LAN address (192.168.1.6 observed), iOS simulator uses localhost. The base URL must therefore be configuration, not a constant.
- (note) Observed today: Ollama is running on localhost:11434 and MedGemma1.5:latest (3.3 GB) is already pulled. /api/tags responded.
- (constraint) OpenAI clients are constructed in three places today: src/utils/openai.js plus inline clients in src/screens/DietScreen.js (lines 22-24) and ExerciseScreen.js (lines 27-29), all hardcoded to https://api.openai.com/v1. Exactly one place may construct a client after this work.
- (note) Both screens call callGPTAPI(prompt) with a single argument; the helper's model and temperature parameters default to gpt-4o and 0.7, which is wrong for a local model. The signature must stop defaulting to a cloud model.
- (constraint) Credentials must not be committed: .env is gitignored and .env.example currently holds only API_GPT_KEY. New profile variables go in .env.example with non-secret placeholder values.
- (constraint) react-native-config is wired through android/app/build.gradle (dotenv.gradle) and android/settings.gradle, so env values are compiled into the Android build and a change requires a rebuild, not a Metro reload.
- (constraint) Local models are slower and less reliable than the cloud model; the layer must surface a clear failure to the user rather than hanging, so an explicit timeout is required.
